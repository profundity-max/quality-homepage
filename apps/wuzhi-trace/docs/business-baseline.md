# 物资申领与消耗追溯 V1.1.1 业务基线

## 1. 目标

以一份可追溯台账管理品质部物资的采购、到货、实收、分发和领用确认，实时给出剩余库存、安全库存告警和预估可用天数，减少表格分散与跨区域口头确认。

## 2. 用户与权限

- 管理员：维护物料档案、成员、部门和区域；可修改、删除、恢复全部记录。
- 文员：登记采购、到货、实收和分发；可查看全部业务台账。
- 区域领用人：提交本人申领/业务单据，只确认所属区域的分发单。
- 品集身份是生产环境的唯一登录依据；应用成员名单只补充区域，不替代品集角色。

## 3. 主流程

1. 管理员建立物料档案。
2. 文员登记采购单。
3. 文员按采购单登记到货批次。
4. 文员对到货批次执行一次实收签收。
5. 文员选择一个已签收批次进行区域分发。
6. 区域领用人对分发表单签字确认。
7. 仪表盘按已签收数量和已分发数量计算库存，按近 30 天分发量估算可用天数。
8. 用户导出月度汇总、全量台账或 CSV。

## 4. 强制业务规则

- 采购、到货、实收和分发数量必须大于 0。
- 到货物料必须与采购物料一致，累计到货不能超过采购数量。
- 同一到货批次只能签收一次，实收数量不能超过到货数量。
- 未签收到货批次不能分发。
- 同一到货批次的累计分发数量不能超过实收数量。
- 同一分发单只能签字确认一次。
- 区域领用人只能确认所属区域，签字人必须与品集登录姓名一致。
- 非管理员只能修改本人创建的业务单据，不能修改创建人。
- 客户端日志不作为权威审计；服务端 `audit.jsonl` 是追溯依据。

## 5. 输入与输出

- 输入：页面表单、OA 请购提报工作簿、系统模板 Excel/CSV、整库 JSON 备份。
- 输出：月度汇总 Excel、全量台账 Excel、CSV、整库 JSON 备份。
- 导入到货时自动补建关联采购；导入分发时自动补建采购、到货和实收链路，避免生成断链记录。
- 导出文件不包含任何设备外部代号，统一使用内部代号。

## 6. 并发与一致性

- 每条记录按字段级最后写入时间合并，同一毫秒冲突使用稳定决胜键，保证交换律。
- 删除使用全局墓碑；旧客户端不能复活已删除记录。
- 写入队列按记录串行提交，断网时保留在本机并在恢复后补传。
- 拉取服务端数据后清除“本机待传”标记，避免拉取和推送形成循环。
- SSE 中断时自动启用 8 秒轮询兜底。

## 7. 异常与恢复

- 主数据文件损坏时服务拒绝启动，不自动用空数据覆盖。
- 每次业务写入自动生成快照；备份失败和审计写入失败通过响应告警暴露。
- 管理员可从 JSON 备份整库恢复；恢复前需要两次确认，接口还会要求管理员身份和 `REPLACE_ALL` 确认。
- 清空或恢复时，对当前存在但恢复包中不存在的记录生成墓碑。

## 8. 验收标准

- 五条主流程记录可按采购、批次、签收、分发、签字逐级追溯。
- 未签收分发、超实收分发、重复签收、重复签字和跨区域签字均被服务端拒绝。
- 重启服务后记录、墓碑和审计仍存在。
- 品集未登录或无有效入口 Cookie 时，页面、静态资源和 API 均不能访问。
- 品集管理员、编辑者、阅读者分别映射为应用管理员、文员、区域领用人。
- 品集加密备份包含物资追溯数据目录。

## 9. 当前不包含

- 条码扫描、ERP 自动对接、邮件/短信通知、合法电子签章、移动端原生应用。
- 外部设备代码展示；所有数据和报表都禁止出现设备外部代号。
