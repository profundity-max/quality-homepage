# 物资申领与消耗追溯 V1.2.7 业务基线

## 1. 目标

以一份可追溯台账管理品质部物资的采购、审核、核准、到货、实收、分发和领用确认，实时给出剩余库存、安全库存告警和预估可用天数，减少表格分散与跨区域口头确认。

## 2. 用户与权限

- 系统管理员：武欣雨、熊光芬，维护成员名单、部门、区域和物料档案，并可处理业务恢复；采购审批仍只允许单据快照中指定的审批人执行。
- 审核员：可按成员名单被指定为审核人，处理分配给自己的采购一级审核；可登记到货、实收和分发。
- 核准员：可按成员名单被指定为核准人，处理两级审批的最终核准或直接核准；可登记到货、实收和分发。
- 区域领用人：提交本人采购申请，可查看本区域分发并确认本区域领用。
- 隶属区域领用人：提交本人采购申请，只能查看和确认分配给本人的分发单。
- 品集身份是生产环境的唯一登录依据。登录后以品集账号优先、历史数据以姓名兜底匹配成员名单，自动带出部门、业务角色、区域和上级；个人不可修改。
- 未匹配成员名单时允许只读查看，但禁止提交采购、审批、到货签收、分发和领用签字，并提示联系系统管理员。

## 3. 主流程

1. 系统管理员建立物料档案和成员名单。
2. 管理员在成员名单中为提交人配置审批模式、指定审核人和指定核准人。
3. 两级审批：申请人提交后进入「待审核」；指定审核人通过后进入「待核准」；指定核准人最终核准后进入「已核准」。
4. 直接核准：申请人提交后跳过审核，直接进入「待核准」，只能由指定核准人处理。
5. 仅审核：申请人提交后进入「待审核」，指定审核人通过后直接完成审批。
6. 驳回必须填写原因；审核人、核准人、审批时间、意见和驳回原因写入操作日志与服务端审计。
7. 采购提交时固化审批路由快照；后续修改名单只影响新提交或驳回后重新提交的单据，不改变在途单据。
8. 审核员或核准员按已核准采购登记到货批次。
9. 审核员或核准员对到货批次执行一次实收签收。
10. 审核员或核准员选择一个已签收批次，指定区域内的区域领用人或隶属区域领用人进行分发。
11. 区域领用人确认本区域单据；隶属区域领用人只确认分配给本人的单据。
12. 仪表盘按采购日期、到货日期、签收日期分别汇总 OA请购、行政请购和其他来源；OA与行政卡片之和加其他来源等于全量指标。
13. 仪表盘按已签收和已分发数量计算库存，按近 30 天分发量估算可用天数。
14. 用户导出月度汇总、OA/行政来源明细、全量台账或 CSV。

## 4. 强制业务规则

- 采购单必须按成员名单路由流转：两级审批为「待审核 → 待核准 → 已核准」，直接核准从「待核准」开始，仅审核从「待审核」直接完成。
- 只有单据快照中的指定审核人可以执行一级审核，只有指定核准人可以执行最终核准；管理员不能替代未分配的审批人。
- 审批人不能修改申请人填写的采购业务内容；采购业务字段只允许申请人或系统管理员修改。
- 审批路由必须引用启用且角色匹配的审核员和核准员；缺失时禁止提交并提示联系管理员。
- 未核准采购不能到货；已核准采购普通用户不能直接修改。
- 采购、到货、实收和分发数量必须大于 0。
- 到货物料必须与采购物料一致，累计到货不能超过采购数量。
- 同一到货批次只能签收一次，实收数量不能超过到货数量。
- 未签收到货批次不能分发。
- 同一到货批次的累计分发数量不能超过实收数量。
- 每张分发单必须指定区域领用人或隶属区域领用人，领用人区域必须与分发区域一致。
- 区域领用人只能确认所属区域；隶属区域领用人只能确认分配给本人的单据。
- 签字人必须与品集登录姓名一致。
- 成员名单仅系统管理员武欣雨、熊光芬可维护；隶属区域领用人必须绑定同区域的区域领用人作为上级。
- 区域角色只能修改本人创建的业务单据，不能修改创建人。
- 客户端日志不作为权威审计；服务端 `audit.jsonl` 是追溯依据。

## 5. 输入与输出

- 输入：页面表单、OA 请购提报工作簿、系统模板 Excel/CSV、成员名单 Excel/CSV、整库 JSON 备份。
- 输出：月度汇总 Excel、全量台账 Excel、CSV、整库 JSON 备份。
- 成员名单导入仅系统管理员武欣雨、熊光芬执行，支持审核员、核准员、区域领用人、隶属区域领用人，以及指定审核人、指定核准人和审批模式；隶属领用人按姓名匹配同区域上级。
- 采购台账页支持导出当前筛选台账、空白采购导入模板和填写说明；导入模板沿用物料档案现有“OA请购提报 V1.0”34列结构，导入仍执行成员审批路由、物料匹配、数量与日期校验。
- 成员名单中的已登记人员可以批量导入或更新物料档案；手工新增、编辑和删除物料仍仅限管理员。
- 采购导入按当前登录人的成员名单路由进入「待审核」或「待核准」；历史到货和分发补链导入仅系统管理员执行，并自动生成已核准采购链路。
- 导出文件不包含任何设备外部代号，统一使用内部代号。

## 6. 并发与一致性

- 每条记录按字段级最后写入时间合并，同一毫秒冲突使用稳定决胜键，保证交换律。
- 删除使用全局墓碑；旧客户端不能复活已删除记录。
- 写入队列按记录串行提交，断网时保留在本机并在恢复后补传。
- 拉取服务端数据后清除“本机待传”标记，避免拉取和推送形成循环。
- SSE 中断时自动启用 8 秒轮询兜底。

## 7. 异常与恢复

- 主数据文件损坏时服务拒绝启动，不自动用空数据覆盖。
- 每次业务写入自动生成快照；备份失败和审计写入失败通过响应告警暴露。
- 管理员可从 JSON 备份整库恢复；恢复前需要两次确认，接口还会要求管理员身份和 `REPLACE_ALL` 确认。
- 清空或恢复时，对当前存在但恢复包中不存在的记录生成墓碑。
- 被下属或历史分发引用的成员只能停用，不能直接删除。

## 8. 验收标准

- 采购单可完整追溯申请人、应审核人、应核准人、实际审核人、实际核准人、审批时间、审批意见和驳回原因。
- 品集账号可自动匹配成员档案并带出部门、业务角色、区域和上级；未匹配账号无法办理业务。
- 两级审批、直接核准、仅审核、指定审批人越权和驳回原因缺失均由服务端拒绝。
- 待审核、待核准、已驳回、已核准状态不能通过普通编辑绕过。
- 未核准到货、未签收分发、超实收分发、重复签收、重复签字和跨区域签字均由服务端拒绝。
- 隶属区域领用人只能确认分配给本人的分发单。
- 成员名单只允许武欣雨、熊光芬维护，隶属领用人的上级必须与其属于同一区域。
- 重启服务后记录、墓碑和审计仍存在。
- 品集未登录或无有效入口 Cookie 时，页面、静态资源和 API 均不能访问。
- 品集加密备份包含物资追溯数据目录。

## 9. 当前不包含

- 条码扫描、ERP 自动对接、邮件/短信通知、合法电子签章、移动端原生应用。
- 外部设备代码展示；所有数据和报表都禁止出现设备外部代号。
