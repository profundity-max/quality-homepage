## 1. 项目目标

### 1.1 一句话定位
面向工厂品质产线（IPQC 2期/3期、OQC、IQC、量测室、实验室等区域）的**物资申领与消耗全流程追溯系统**：采购登记 → 到货登记 → 文员签收 → 物料分发 → 区域领用人签字确认 → 库存/消耗统计仪表盘，全程留痕、多电脑共享、零安装。

### 1.2 硬性目标（按优先级）
1. **零依赖**：前端零外部库（无 CDN、无 npm 运行时依赖）；服务端只用 Node 内置模块 `http/fs/path/os/crypto`；Excel 读写为手写 ZIP+OOXML。
2. **多机共享两种形态**：
   - **云端实时共享**：一台电脑跑 Node 服务（8082 端口），全员浏览器打开同一地址实时协作；
   - **共享文件同步**（V1.1.0「共享直通」）：不监听端口、不建网络连接，靠导出/导入 JSON 共享包在共享盘/企微群/邮件间流转，**天然免防火墙**。
3. **并发录入不冲突**：两人同时录入/修改，按「每条记录 + 每个字段」独立合并，双方改动都保留。
4. **严格对齐 OA 模板**：导出/导入严格复刻《OA请购提报模板 V1.0.xlsx》34 列结构、样式零差异（表头填充/字体/边框/列宽/行高/数字格式）。
5. **离线可用**：断网时本地录入不丢，恢复后自动补传；清浏览器缓存/换电脑不丢数据（服务端文件是唯一真本）。
6. **可追溯**：所有操作写操作日志（谁、何时、动作、对象、详情）。

### 1.3 命名演进（最终正式命名）
`物资申领与消耗追溯-多用户版` → `物资申领追溯V1.0`（统一项目名）→ `物资申请追溯系统11.16/11.17共享版/并发版/修复版` → **最终：`物资申领追溯系统V1.1.0「共享直通」版`**。交付件三件套：单文件 HTML、完整部署包 ZIP、发布说明 MD。

## 2. 总体技术方案

### 2.1 架构总览
```

│ 浏览器A/B/C（零安装）                                  │

│   │ ②SSE 实时推送 /api/events（15s 心跳，30s 轮询兜底）│
│   ▼                                                  │
│ server.js（Node 零依赖，监听 0.0.0.0:8082）           │
│   ├─ 逐条字段级 LWW 合并 → 权限校验 → 原子落盘         │
│   ├─ data/store.json（唯一真本）+ backup/（200份）     │
│   └─ data/oplog.jsonl（变更流水）                     │
└──────────────────────────────────────────────────────┘
┌─ 模式B：共享文件同步（免防火墙）──────────────────────┐
│ 每人浏览器 → 导出 JSON 共享包（全量/增量）             │
│   → 共享盘/企微群/邮件流转 → 各自「合并导入」          │
│ 合并 = mergeStates 字段级 LWW，与导入顺序无关          │
│ 不监听端口、不入站连接 → 防火墙完全不参与              │
└──────────────────────────────────────────────────────┘
┌─ 模式C：本地单机（降级兜底）──────────────────────────┐
│ 数据存 localStorage，双击 HTML 即用                   │
└──────────────────────────────────────────────────────┘
```

### 2.2 技术栈
| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | 原生 HTML/CSS/JS（ES2020+） | 三个文件：`index.html`（结构+样式）、`core.js`（内核）、`views.js`（视图）；另有打包脚本可合成单文件 HTML |
| 服务端 | Node.js `http.createServer` | 零依赖；静态托管 + REST + SSE |
| Excel | 手写 ZIP（CRC32 + CompressionStream deflate-raw）+ OOXML | 导出 `xlsxBuild`（通用）/`xlsxBuildOA`（OA 模板复刻）；导入 `xlsxRead`（正则解析 worksheet XML + sharedStrings） |
| 持久化 | JSON 文件 + 原子写（tmp→rename） | 服务端 `data/store.json`；前端 localStorage（`WZ_DATA_V1` 等键） |
| 实时通道 | SSE（EventSource） | 失败降级为 8 秒轮询；另加 30 秒兜底拉取 |

### 2.3 关键设计决定（不可妥协）
1. **字段级时间戳是并发安全的地基**：每条记录除记录级 `ts` 外，每个字段有独立时间戳 `f[k]`。只给「用户确实动过」的字段打新时间戳（与编辑基线 EDIT_BASE 对比判断），未动字段保留原值原时间戳——这是「两人同时改同一单的不同字段互不覆盖」的根本。
2. **合并满足交换律**：`mergeRec(a,b)` 与 `mergeRec(b,a)` 结果必须相同。同毫秒并发按 `(by, 内容排序后 JSON)` 的稳定字典序 tieKey 选出唯一胜者，否则两台机器各自合并后可能长期互相顶回。
3. **删除用墓碑（tomb）**：`tomb[id] = 删除时间戳`；合并时 `tomb[id] >= rec.ts` 则记录不复活。提交旧表单版本时若记录已被他人删除（`tombT >= baseTs && tombT < rec.ts`），服务端返回删除裁决让前端同步删除，绝不复活。
4. **服务端是唯一裁判**：写权限校验 `checkWrite` 在服务端强制执行；前端隐藏按钮只为体验。身份是「自报姓名的可信内网模型」，管理员口令是唯一服务端硬校验。
5. **同毫秒/时钟问题**：前端 `nextTs()` 保证新 ts 严格大于原记录 ts；服务端 `MAX_SKEW=10min` 封顶未来时间戳，防本机时钟跑飞永久压住别人的修改。
6. **口令归一化 `normKey()`**（两侧同一套规则）：trim + NFKC + 剥离零宽字符（\u200B-\u200F、\u202A-\u202E、\u2060、\uFEFF）。修复「从微信/文档复制口令校验失败」。HTTP 头不允许非 Latin-1 字符，中文身份头用 `encodeURIComponent` 传输。

## 6. 合并算法（核心，必须逐条复刻）

### 6.1 normalize(raw)：脏数据→标准结构
- 兼容 `data` 包裹/裸对象/数组/Object.values 三种来源；记录无 id 丢弃；`tomb[id] >= rec.ts` 的记录剔除；字段无独立时间戳回退记录级 `f[k]=r.ts`。**不塞种子数据**。

### 6.2 mergeRec(a, b)：字段级 LWW（交换律保证）
```
1. base = ts 大的一方；ts 相同 → tieKey 字典序大的一方
   tieKey(r) = String(r.by) + '#' + JSON.stringify(sortKeys(r))   // 递归排序键
2. 先复制 base 的字段（字段用自己的 f[k]，绝不能用记录级 ts 顶上去——
   否则「只改用途」的人会把没改的数量也标成刚改，盖掉别人刚改的数量）
3. 遍历 other：字段时间戳 ot > 当前 bt → 覆盖该字段
4. 返回前按 normRec 键序重排——否则 merge 产物与 normalize 产物 JSON 串不同，
   会被 checkWrite/sameRec 误判成「有改动」，导致正常提交被当越权拒绝（实际踩过的坑）
```

### 6.3 mergeStates(sA, sB)
墓碑取双方最大值 → 各集合逐 id mergeRec → 剔除被墓碑覆盖的 → `ver/max updatedAt` 归并。

### 6.4 前端 upsert 的字段级改动判定
```js
// EDIT_BASE：markEdit(coll,id) 在打开编辑窗时快照整条记录
// 判断「改了哪个字段」跟打开窗口时的值比，不是跟此刻服务端最新值比，
// 否则填表期间别人改了别的字段，表单回传旧值会把别人的改动当成「改回去」
rec.f[k] = Math.max(t, prevF+1)   // 改动的字段：打新时间戳
// 未改动字段：保留当前值（可能已被别人改过）与其时间戳，不用表单旧值写回
// 表单没提交的字段：原样保留（含时间戳），防被当成删除字段
```

## 7. 服务端接口设计（server.js，零依赖 Node）

### 7.1 全局约定
- 端口：`process.env.PORT || WZ_PORT || config.port || 8082`；监听 `0.0.0.0`。
- CORS：`*` 全放行；允许头 `content-type, x-share-token, x-admin-key, x-user-name, x-user-role, x-user-region`。
- 鉴权：可选访问令牌 `x-share-token` 头或 `?token=`（config.token）；管理员 = `x-admin-key` 头或 body.adminKey，经 `normKey()` 后与 `ADMIN_KEY` 比较（来源优先级 env `WZ_ADMIN_KEY` > config.adminKey > 默认 `wuzhi-admin-2026`，来源随接口下发为 `adminKeySource: 'env'|'config'|'default'`）。
- 身份头：`x-user-name/role/region`（前端 encodeURIComponent，服务端 decodeURIComponent）。
- 请求体上限 64MB；`MAX_SKEW = 10min`（时钟超前封顶）。
- 构建指纹 BUILD_ID：启动时对 public/ 全文件做 sha1 前12位，随 `/api/health`、`/api/store`、`/api/build` 下发，前端可感知服务端新版本。

### 7.2 接口清单

**GET /api/health** →
```json
{ ok:true, ver, build, records, items, online:["张三","李四×2"], needToken, title, adminKeySource }
```

**POST /api/verify-key**（口令即时校验，修复 2026-11-17）body `{adminKey}` →
```json
{ ok:true, isAdmin, adminKeySource, len, hadInvisible, hadFullWidth }
// 不回显口令本身；hadInvisible/hadFullWidth 用于前端诊断提示
```

**GET /api/build** → `{ ok, build, serverTime }`

**POST /api/wipe**（清空云端，仅管理员）body `{adminKey}` → 校验通过则 STATE=空库、ver=1、CHANGES 清空、广播 update → `{ok, ver}`；失败 403 `{ok:false,error}`。

**GET /api/store?since=N**（拉取；支持增量）
- 无 since 或增量日志不完整 → 全量：
```json
{ ver, updatedAt, updatedBy, isAdmin, scope:"all"|"mine", boot, seq, adminKeySource,
  user:{name,role,region}, build, data:{...8集合,tomb} }
```
- `since` 合法且变更日志完整 → `{ partial:true, ver, seq, boot, isAdmin, scope, changes:[{coll,id,rec|tomb}], serverTime, adminKeySource }`。
- 变更日志机制：内存 `CHANGES=[{seq,coll,id}]` 上限5000条，每次提交 `noteChanges(prev,next,seq)` diff 出实际变化的记录；`changesSince(since)` 检查 `out[0].seq > since+1`（有被淘汰版本）则返回 null 让前端整库拉。

**POST /api/ops**（主写通道，逐条记录提交）
body：
```json
{ ops:[{coll,id,rec,ts,baseTs} | {coll,id,del:true,ts}],
  ver, client, name, role, region, adminKey }
```
处理逻辑（≤3000条）：
1. 逐条校验：coll 白名单、id 合法（≤64、无 `/`）、rec 非空、有 ts；
2. `checkWrite` 权限校验（见 §9）；
3. 删除 op：记录已被他人更新（existing.ts > ts）→ 不生效并带 note；墓碑已更晚 → 幂等成功；否则写 tomb、删记录；
4. 写 op：`ts > now+SKEW` 封顶；字段时间戳同样封顶；墓碑已覆盖 → 不复活并回传删除裁决；`tombT >= baseTs && tombT < rec.ts`（提交的是打开表单时的旧版、期间被删）→ applied 带删除裁决 + rejected 说明；否则 `mergeRec(existing, rec)` 合并（新记录直接落）；`sameRec(existing, merged)` 幂等跳过；
5. `touched>0` → ver+1、noteChanges、persist、`broadcast('update',{ver,by}, 排除发起 client)`；
6. 响应：`{ ok, ver, seq, boot, applied:[{coll,id,rec|del,ts,note?}], rejected:[{coll,id,reason}], touched, serverTime }`。

**PUT /api/store**（兼容保留的整库提交，不再支持 force 覆盖）
`checkWrite` 全量校验通过后一律 `mergeState` 合并（任何提交一律合并，不用本机数据覆盖云端）；响应 `{ver, conflict, data}`。

**GET /api/events?client=&name=**（SSE）
- 事件：`hello {ver,clientId}`、`presence {online:[...]}`（连接/断开时广播）、`update {ver,by}`（排除发起者）；15s 心跳注释行；EventSource 自带重连，前端另设 8s 轮询降级与 30s 兜底拉取。

### 7.3 静态托管与启动
- `serveStatic`：路径穿越防护（normalize 后必须 startsWith PUB_DIR）；MIME 表含 html/js/css/json/png/ico。
- 启动横幅：打印本机/局域网/主机名地址、记录数、数据目录、口令来源、构建指纹、防火墙提示；写 `访问地址.txt`（含虚拟网卡过滤排序：vmware/virtualbox/hyper-v/docker/wsl 等排后）。
- 非沙箱环境自动打开浏览器；`EADDRINUSE` 明确报错退出。
- `module.exports = { mergeState, normalize, COLLECTIONS, FIELDS, countRecords, checkWrite, ADMIN_ONLY_COLLS }` 供单测 require。

## 8. 前端同步层设计（core.js）

### 8.1 SYNC 状态对象
```js
SYNC = { mode:'local'|'server', ver, seq, server, online[], conflict, es, pollT, pushT, autoT,
  connected, admin, scope, lastSyncAt, lastError, pushing, adminKeySource }
```

### 8.2 连接发现
- `candidateBases()`：URL `?server=` 参数 → localStorage 保存地址 → 同源（含 `/wz/` 挂载前缀）→ `http://{当前hostname}:8082` → `http://localhost:8082`，去重。
- `upgradeLegacyPort()`：旧端口 8787 自动更正为 8082（结果写回输入框让用户可见）。
- `probeEx(base)`：GET `/api/health` 4 秒超时；失败分类 reason：`empty/timeout(AbortError)/refused/http<code>/badreply`，驱动用户可读诊断文案（含「一键启动_自动放行防火墙.bat」指引）。
- `autoDetect()`：逐候选探测，首个命中即用。

### 8.3 写通道（ops 队列，串行）
- `queueOp(coll,id,rec,del,ts,baseTs)`：key=`coll/id`，同记录多次改动只留最后一次（天然去重）；baseTs=打开编辑窗时记录版本（服务端用于「已被删的旧数据」判断）；落 localStorage，上限3000条按 seq 淘汰。
- `flushOps()`：Promise 链串行队列，绝不允许两个请求同时在路上；220ms 防抖批量发送。
- 失败处理：网络异常 → 指数退避（800ms 起步，上限15s）自动重试 + toast「改动已保存在本机」；401/403 → 不重试，刷新为云端权威数据 + 明确提示；rejected 逐条剔除不重试。
- 服务端裁决采纳：applied 逐条 mergeRec 合入本地（含删除裁决同步删墓碑）；contested 计数 → toast「已自动合并 n 条他人同时修改（双方改动都保留）」。

### 8.4 读通道
- `pullStore(force)`：Promise 链串行；`?since=SYNC.seq` 增量（有待传 op 时禁用增量防吞并）；`applyChanges` 逐条合并（rec=null 删本地、tomb 更新墓碑）。
- 全量拉取三种分支：① 服务端空库+本机有数据 → 播种（本机数据 push 上去）；② 本机有未推送改动 → `mergeStates(server, local)` + 补传；③ 常规 → 采纳服务端（ver 未变且已连接则跳过重渲染）。
- 实时：SSE `update` 事件 → `j.ver > SYNC.ver` 时触发拉取；`presence` 更新在线名单；SSE 不可用降级 8s 轮询；30s 自动兜底（document.hidden 跳过）。
- 本地持久化 `saveLocal(pend)`：pend=true 仅表示「本机有未推送改动」；**拉取/采纳服务端数据必须传 false，否则形成 拉取→标脏→推送→广播→对端拉取 的无限冲突循环**（踩过的坑）。

### 8.5 身份与权限（前端侧）

## 9. 权限与安全（服务端 checkWrite，口径 2026-11-03 与用户确认）

**总原则：全量可见 + 写权限隔离。**

| 规则 | 实现 |
|---|---|
| ① 物料档案 / 成员名单 | `ADMIN_ONLY_COLLS=['materials','members']`，仅管理员（口令认可）可增改 |
| ② 领用签字 | 区域领用人只能签自己区域（rec.region === who.region）的单 |
| ③ 区域领用人单据归属 | purchases/dispatches/signoffs 中别人（rec.by ≠ 本人）录入的单据只能看不能改 |
| ④ 其余业务记录 | 采购/到货/签收/分发/日志全员可写（多端合并需要携带他人记录） |
| ⑤ 删除 | 非管理员只能删自己创建（tomb 变更时反查 owner=rec.by）；管理员不限 |
| ⑥ 内容等价判定 | `sameRec` 按 sortKeys 排序后比较 JSON——键序不同不算改动（防误判越权） |

安全边界：内网 HTTP 明文（靠不出厂区 + 口令 + 日志兜底）；禁止公网端口映射；口令不回显、诊断信息不含口令原文；`/api/wipe` 服务端二次校验 + 前端二次确认。

## 10. 共享文件同步（V1.1.0「共享直通」核心）

### 10.1 原理
数据本身即「字段级时间戳 f + 记录级 ts + 墓碑 tomb」CRDT 结构 → 各自导出 JSON 包 → mergeStates 字段级合并：不同字段后改者生效、单边记录直接取用、删除按墓碑传递不复活、**与合并顺序无关**。免服务器/免端口/免防火墙。

### 10.2 包格式
```json
{ "tag":"WZ-SYNC-BUNDLE", "ver":2, "mode":"full"|"incremental", "since":0,
  "exportedAt":1731900000000, "exportedBy":"张三", "device":"c_xxx",
  "counts":{...各集合条数,total}, "data":{...8集合,tomb}, "stateVer":n, "stateUpdatedAt":n }
```
- **增量包**：`since=上次导出时间(WZ_LAST_EXPORT_AT)`，记录按 `recTouchTs(r)=max(ts, max(f[k]))` 过滤，墓碑按时间戳过滤；与全量包合并结果一致但体积小。
- 文件名：`物资共享包_{姓名}[_增量]_{YYYYMMDD_HHMMSS}.json`。
- 首次必须全量（未导出过全量包时点增量会被拦截提示）。

### 10.3 合并导入
- 兼容三种来源：本模块共享包 / 服务器 store.json 备份 / 裸 data 对象。
- **重复包识别**：`seenKey = device@exportedAt`（仅 tag 匹配时），已合并过的直接 `skipped`，防手抖重复导入误判。
- UI 支持多选文件 + `webkitdirectory` 选整个共享文件夹（自动过滤 .json）；按 `exportedAt` 从旧到新排序依次合并；结果报告 `✓ 合并 n 条新增 / ↷ 重复跳过 / ✗ 失败原因`。
- 在线模式下合并后 400ms 触发 pushStore 把合并成果推回云端。

## 15. 关键踩坑记录（复刻时必须规避）

1. **mergeRec 必须满足交换律**，同毫秒并发用 tieKey 决胜，否则多机长期互相顶回。
2. **base 字段合并用自己的字段时间戳**，不能用记录级 ts 顶上去。
3. **merge 产物必须 normRec 重排键序**，否则 JSON 串不同被 sameRec/checkWrite 误判。
4. **upsert 只给真改动的字段打新时间戳**（与 EDIT_BASE 比，不是与服务端最新值比）。
5. **拉取服务端数据后 saveLocal(false)**，否则拉取→标脏→推送死循环。
6. **被拒绝的 op 不能重试**（越权/已被删），否则无限循环。
7. **HTTP 头不支持非 Latin-1**：中文身份头必须 encodeURIComponent；口令含零宽字符时 fetch 直接抛异常 → normKey 两侧统一。
8. **时钟跑飞封顶 MAX_SKEW**，未来时间戳会永久压住别人的修改。
9. **删除优先**：旧表单版本提交时若记录已被删（tomb>=baseTs），不复活并回传删除裁决。
10. **库存 KPI 必须用全量数据算**，列表级「只看自己」不能作用到库存底座，否则余量虚高。
11. **空服务器播种 / 有待传先合并再补传**，任何情况下不允许整库 force 覆盖云端。
12. **Edit 工具偶发未落盘**：每次修改后必须 grep/node 复核。
13. **服务端构建指纹必须核对**：现场「口令连不上」根因常是旧进程旧构建（verify-key 404），不是口令本身。
