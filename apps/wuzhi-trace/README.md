# 物资申领与消耗追溯 V1.2.7

品集｜Q Nexus 应用中心内的受控物资管理应用，负责采购两级审批、OA/行政请购来源分析、物料档案、到货签收、区域分发、领用确认、库存预警和台账导出。

## 运行位置

- 生产环境：作为 `wuzhi-trace` 容器与品集 Web、PostgreSQL、Nginx 同栈运行。
- 外部入口：只允许从品集应用中心的“打开物资追溯系统”进入。
- 登录方式：品集短期签名授权经 Nginx 校验后，以内部身份头传给应用；应用不保存管理员口令。
- 数据目录：`/app/data/wuzhi-trace`，位于品集受控数据卷内，随品集加密备份一起保存。

## 业务角色

| 业务角色 | 主要权限 |
| --- | --- |
| 审核员 | 可按成员名单被指定为审核人，执行分配给自己的一级审核，并可登记到货、实收和分发 |
| 核准员 | 可按成员名单被指定为核准人，执行分配给自己或直接核准的审批，并可登记到货、实收和分发 |
| 区域领用人 | 提交本人采购、查看本区域分发并确认本区域领用 |
| 隶属区域领用人 | 提交本人采购，只查看和确认分配给本人的分发 |

用户从品集应用中心登录后，应用以品集账号优先、历史数据以姓名兜底自动匹配成员名单，并从成员档案读取部门、业务角色、区域和上级。个人不能在应用内修改这些信息；未匹配成员名单时允许查看数据，但禁止提交采购、审批、到货签收、分发和领用签字，并提示联系系统管理员。

品集角色仅用于未匹配成员时的显示兜底：`administrator → 核准员`、`editor → 审核员`、`reader → 区域领用人`。未匹配身份不具备业务办理权限。

系统管理员为武欣雨、熊光芬，负责成员名单、部门、区域和物料档案维护。成员名单中的已登记人员可以通过 Excel/CSV 导入或更新物料档案，但不能手工新增、编辑或删除物料。成员记录可通过品集账号或显示名匹配登录身份。

## 采购流程

1. 管理员在成员名单中为每位提交人配置审批模式、指定审核人和指定核准人。
2. 两级审批：申请人提交后状态为「待审核」；指定的审核人通过后进入「待核准」；指定的核准人完成后进入「已核准」。
3. 直接核准：申请人提交后跳过审核，直接进入「待核准」，只有指定核准人可以处理。
4. 仅审核：申请提交后进入「待审核」，指定审核人通过后直接完成。
5. 驳回必须填写原因；审核人、核准人、审批时间、意见和驳回原因进入客户端操作日志及服务端审计。
6. 采购提交时把审批路由快照固化到单据，后续修改成员名单不改变在途单据；新提交或驳回后重新提交时按当时名单重新匹配。
7. 审批人只能处理分配给自己的待办，不能修改申请人填写的采购业务内容；职责分离由前端显隐和服务端校验共同保证。
8. 未配置审核人 / 核准人或提交人未匹配成员名单时，服务端拒绝提交，并提示联系管理员。
9. 只有「已核准」采购可以登记到货；已驳回采购由申请人修改后重新提交。
10. 已核准采购普通用户不能直接修改；系统管理员修改后重新进入审批流程。

## 采购台账 Excel

- 采购台账页可导出当前月份 / 物料筛选结果，并同时生成“采购台账”“导入模板”“填写说明”三张工作表。
- 导入模板严格沿用物料档案现有“OA请购提报 V1.0”的34列表头，包括申请人、申请部门、项目、物品类型、存货编码、存货名称、规格型号、请购数量、申请时间、地点和申请原因等。
- 采购台账页可直接导入 `.xlsx/.csv`；导入时优先读取“导入模板”工作表，并按当前登录人的成员名单审批路由生成采购单。
- 未匹配物料时会按 Excel 信息自动创建物料档案；OA模板默认归入“OA请购”，采购数量与申请时间由导入程序校验。
- XLSX 读取兼容 Excel 生成的数字字符实体，避免中文表头被识别为 `&#...;` 文本。

## 本地独立运行

```bash
npm start
```

默认地址为 `http://localhost:8082/`。独立模式用于本地开发和应急诊断，生产环境必须使用 `QNEXUS_SSO=1`。

## 数据安全

- 主数据文件采用临时文件 + `fsync` + 原子重命名，不静默用空数据覆盖损坏文件。
- 每次业务写入生成 `backup/store-*.json`，默认保留 200 份。
- `audit.jsonl` 记录版本、操作人、品集 subject、动作、集合、记录标识和变更字段。
- 整库恢复只允许管理员执行，并要求明确确认；恢复和清空会生成墓碑，防止旧客户端复活记录。
