# 物资申领与消耗追溯 V1.2.0

品集｜Q Nexus 应用中心内的受控物资管理应用，负责采购两级审批、物料档案、到货签收、区域分发、领用确认、库存预警和台账导出。

## 运行位置

- 生产环境：作为 `wuzhi-trace` 容器与品集 Web、PostgreSQL、Nginx 同栈运行。
- 外部入口：只允许从品集应用中心的“打开物资追溯系统”进入。
- 登录方式：品集短期签名授权经 Nginx 校验后，以内部身份头传给应用；应用不保存管理员口令。
- 数据目录：`/app/data/wuzhi-trace`，位于品集受控数据卷内，随品集加密备份一起保存。

## 业务角色

| 业务角色 | 主要权限 |
| --- | --- |
| 审核员 | 提交采购、执行一级审核，并可登记到货、实收和分发 |
| 核准员 | 提交采购、执行最终核准，并可登记到货、实收和分发 |
| 区域领用人 | 提交本人采购、查看本区域分发并确认本区域领用 |
| 隶属区域领用人 | 提交本人采购，只查看和确认分配给本人的分发 |

品集角色作为未配置成员时的默认映射：`administrator → 核准员`、`editor → 审核员`、`reader → 区域领用人`。成员名单中的业务角色和区域优先。

系统管理员固定为武欣雨，负责成员名单、部门、区域和物料档案维护。成员记录可通过品集账号或显示名匹配登录身份。

## 采购流程

1. 申请人提交采购，状态为「待审核」。
2. 审核员审核通过后进入「待核准」，也可填写原因驳回。
3. 核准员最终核准后进入「已核准」，也可填写原因驳回。
4. 只有「已核准」采购可以登记到货；已驳回采购由申请人修改后重新提交。
5. 已核准采购普通用户不能直接修改；系统管理员修改后重新进入「待审核」。

## 本地独立运行

```bash
npm start
```

默认地址为 `http://localhost:8082/`。独立模式用于本地开发和应急诊断，生产环境必须使用 `QNEXUS_SSO=1`。

## 验证

```bash
npm run check
npm test
```

测试覆盖两级审批流、字段级合并、墓碑删除、主业务流程、数量上限、区域与隶属领用人签字、成员维护权限、品集身份映射、SSO 静态资源保护、持久化和整库恢复。

## 代码结构

```text

```

## 数据安全

- 主数据文件采用临时文件 + `fsync` + 原子重命名，不静默用空数据覆盖损坏文件。
- 每次业务写入生成 `backup/store-*.json`，默认保留 200 份。
- `audit.jsonl` 记录版本、操作人、品集 subject、动作、集合、记录标识和变更字段。
- 整库恢复只允许管理员执行，并要求明确确认；恢复和清空会生成墓碑，防止旧客户端复活记录。
