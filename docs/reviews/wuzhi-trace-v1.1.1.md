# 物资申领与消耗追溯 V1.1.0 审查与 V1.1.1 优化记录

日期：2026-11-18

## 审查方式

以压缩包内的 V1.1.0 源码、完整开发方案和使用说明为输入，分别检查代码规范与需求实现，并补充运行级验证。

## Standards 结论

| 等级 | 问题                                                         | 处理                                                                                |
| ---- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| P0   | 服务端信任客户端姓名、角色和区域，前端过滤不能替代服务端授权 | 品集生产模式改为只接受 Nginx 转发的签名身份头；独立模式保留本地身份但由后端统一校验 |
| P0   | 客户端可伪造业务日志，原 `oplog.jsonl` 只有版本和记录总数    | 新增服务端 `audit.jsonl`，记录操作人、品集 subject、动作、集合、记录和变更字段      |
| P1   | 数据恢复使用普通整库 PUT，既不能真正覆盖，失败也可能提示成功 | 新增管理员专用 `/api/restore`，要求明确确认并检查 HTTP 状态                         |
| P1   | 合并、权限、持久化、HTTP 路由混在单个文件                    | 拆分为 model、business-rules、identity、store-repository、HTTP 五个模块             |
| P1   | 测试写死 Windows 路径且依赖未声明的 `jsdom`                  | 新增可移植 Node 内置测试，覆盖单元、集成、SSO 和持久化                              |

## Spec 结论

| 等级 | 问题                                                          | 处理                                                                |
| ---- | ------------------------------------------------------------- | ------------------------------------------------------------------- |
| P0   | 区域领用人可越区签字，原校验读取了签字记录中不存在的 `region` | 改为通过 `did` 找到分发单并校验分发区域；签名人必须等于品集登录姓名 |
| P0   | 未签收也能分发，且可超过实收数量                              | 前端只列出已签收批次；后端强制校验签收存在、累计分发不超过实收      |
| P0   | 重复签收和重复签字可并发产生                                  | 后端分别限制同一到货批次一次签收、同一分发单一次签字                |
| P1   | Excel 导入生成无采购/批次关联的断链记录                       | 导入时自动补建采购、到货、实收链路                                  |
| P1   | 拉取服务端数据后未清除待传标记，可能形成反复推送              | `saveLocal(false)` 现在显式移除待传标记                             |
| P1   | SSE 出错后没有真正启用轮询兜底                                | SSE 断开时启用 8 秒轮询，连接恢复后停止                             |
| P1   | 纯 data 对象与文档声明不兼容                                  | 共享包合并现已识别裸 data 对象                                      |

## 保留边界

- 浏览器“操作日志”继续作为用户可读活动记录，但服务端审计才是权威追溯来源。
- 区域领用人需要在应用成员名单中存在同名成员并配置区域；否则系统拒绝签字并提示管理员维护。
- 当前应用仍使用 JSON 主数据文件而非 PostgreSQL；已通过原子写入、快照、墓碑、字段级合并和服务端审计控制风险，后续数据量显著增长时再评估迁移数据库。
