# 使用 Nginx 作为本地反向代理

品集｜Q Nexus 的 Compose 运行形态使用 Nginx unprivileged 镜像作为唯一发布宿主端口的反向代理。它只承担内部 HTTP 入口、转发和基线安全响应头，不承担公司证书签发、固定局域网地址或访问控制策略。

选择 Nginx 是因为 Slice 1 只需要静态、可离线验证的代理规则，unprivileged 镜像可在非 root 端口上运行，且无需运行时控制面或公网依赖。早期实施计划中记录的 Caddy 方案由本决策替代；若公司 IT 后续确定由容器直接终止 HTTPS，可重新评估代理实现。无论代理产品如何变化，ADR 0001 与 ADR 0004 规定的最小暴露面、离线可用性和内部 HTTPS 扩展边界保持不变。
