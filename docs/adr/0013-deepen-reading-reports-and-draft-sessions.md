# ADR 0013: 阅读、统计用途和编辑草稿会话的职责深化

- 状态：已接受，V7.0 生效
- 日期：2026-10-22
- 来源：架构巡检三项建议与用户逐项实施要求
- 关联：ADR 0004、0011、0012

活跃阅读的状态转换、暂停修订、节流和请求排序归 client-session module。ReadingTracker 作为浏览器 adapter，只采样文章可见性、焦点和交互并执行请求。测试跨同一 interface 重放在途请求、失焦、切换和离页；最新采样使等待中的旧选择失效。保留服务器计时、20秒租约和客户端10秒采样，不改变学习参与统计口径。

学习报表 module 共享权限、时间窗口、人员筛选和排序口径，增加人员专用汇总用途。人员导出无需构建内容排名、趋势和逐条明细，也不读取文章与模板元数据；保留生成文件后先审计再返回。完整报表通过分组索引避免逐人、逐文章、逐日扫描全部事件。知识缺口沿用独立搜索口径，通过独立查询取得，不再执行整份旧 dashboard。仍采用部门规模的时间窗口读取，不增加通用 repository 或预聚合数据结构。

编辑草稿会话归 offline-drafts/session module：自动保存、在线状态、本地恢复、冲突选择、revision 和清理时机集中管理。编辑器是读取当前输入、调用保存动作和展示结果的 adapter。响应只确认发送时的快照，在途输入另存本地；恢复尚未选择时，断网和清理不得覆盖恢复副本。选择服务器版本终结本次会话，销毁不得重新捕获被丢弃的正文。浏览器存储不可用不阻断服务器保存，失败提示不能宣称本地保存成功。

数据库事务、编辑占用及乐观版本继续由 ADR 0011 的所属 module 管理。本次不增加持久化结构、不新增计时数据，也不把本地正文保存扩展为完整离线编辑器。剩余限制：浏览器强制结束、存储被清理或网络长时中断仍不能保证所有未提交输入恢复。
