# 品集｜Q Nexus 产品需求规格

> 状态：已确认  
> 确认日期：2026-08-12  
> 产品类型：品质部局域网知识门户  
> 领域词汇：[CONTEXT.md](../../CONTEXT.md)  
> 栏目初始结构：[栏目体系.md](../../栏目体系.md)

## 1. 产品定义

品集｜Q Nexus 是面向品质部成员、仅在公司局域网内访问的知识门户。它集中承载新人学习、品质知识、散热与 TVC 知识、工作模板和推荐书目，降低资料查找成本与重复询问，并为内容维护、复核、反馈和统计提供完整治理闭环。

### 1.1 核心目标

1. 新人无需持续口头带领，也能沿明确路线找到入门内容。
2. 品质部成员能通过搜索或栏目导航快速找到知识和模板。
3. 编辑者无需修改代码即可维护、发布、复核和归档内容。
4. 部门能识别热门内容、触达范围和知识缺口，但不将阅读行为用于个人绩效评价。
5. 系统在部门 Mac Studio 上稳定运行，外网中断时仍能完整使用。

### 1.2 设计容量

- 100 个账号
- 5,000 篇知识文章
- 500 GB 模板文件
- 20 人同时在线

这些数字是首版设计容量，不是强制采购或预占资源要求。

### 1.3 明确不做

- 不作为公司官网、个人博客或公开社区。
- 不记录新人个人学习进度、完成率、考试或培训成绩。
- 不提供公开评论、文章评分或社交动态。
- 不承担 QMS 正式文控系统职责。
- 不管理 TVC 设备、试验预约或任务流程。
- 不提供书籍借阅或库存管理。
- 不解析或在线预览模板文件。
- 不自动转换 Word、PowerPoint 或 PDF 为文章。
- 不提供公网访问、远程访问或第三方登录。
- 不承诺首版 7×24 高可用或双机容灾。

### 2.1 角色

| 能力 | 阅读者 | 编辑者 | 管理员 |
| --- | --- | --- | --- |
| 登录、阅读、搜索 | 是 | 是 | 是 |
| 收藏文章 | 是 | 是 | 是 |
| 下载模板 | 是 | 是 | 是 |
| 提交内容反馈 | 是 | 是 | 是 |
| 修改本人显示名称和密码 | 是 | 是 | 是 |
| 创建、编辑、发布和归档内容 | 否 | 是 | 是 |
| 维护学习路线、模板、书目和标签 | 否 | 是 | 是 |
| 处理内容反馈和复核任务 | 否 | 是 | 是 |
| 查看聚合内容统计 | 否 | 是 | 是 |
| 管理账号、角色和栏目 | 否 | 否 | 是 |
| 查看 90 天内身份化搜索与触达明细 | 否 | 否 | 是 |
| 管理回收站、导入导出、审计和备份 | 否 | 否 | 是 |
| 登录 Mac Studio 主机 | 否 | 否 | 不因网站角色自动获得 |

### 2.2 账号与登录要求

- **AUTH-01** 仅管理员可以创建、停用、删除和重置账号；网站不开放自行注册。
- **AUTH-02** 新账号使用临时密码，首次登录必须修改后方可继续使用。
- **AUTH-03** 密码必须使用不可逆、安全的密码哈希保存；界面、数据库可读字段和日志均不得出现明文密码。
- **AUTH-04** 管理员只能重置密码，不能查看或找回原密码。
- **AUTH-05** 连续登录失败后账号应被暂时锁定，管理员可查看锁定状态并安全解锁。
- **AUTH-06** 登录状态默认保持 7 天；登录页允许用户取消“保持登录”。
- **AUTH-07** 管理员可强制指定账号退出所有已登录设备。
- **AUTH-08** 停用账号后禁止登录，但其历史作者、修改者、上传者和审计记录必须保留，并标记“账号已停用”。
- **AUTH-09** 禁止管理员停用当前登录账号，禁止停用或降级最后一名有效管理员。
- **AUTH-10** 首个管理员通过 Mac Studio 上的一次性初始化命令创建，不提供网页端“注册首位管理员”。
- **AUTH-11** 至少配置两名网站管理员，并由两名不同人员分别保管账号。
- **AUTH-12** 账号显示名称用于首页问候；未填写时回退到用户名。

## 3. 信息架构

### 3.1 一级入口

- **IA-01** 全站一级入口包括：首页、新人专区、品质知识、散热知识、推荐书单、模板中心。
- **IA-02** 首页使用顶部主导航；品质知识和散热知识页面增加可收起的左侧分类树。
- **IA-03** 页面地址使用不会随标题变化的内部标识；文章、主题或栏目改名不得破坏旧链接。

### 3.2 品质知识分类

- **IA-04** 初始分类树采用 [栏目体系.md](../../栏目体系.md) 中的结构。
- **IA-05** ANOVA、MSA、SPC、CAPA 等末级节点定义为“主题”，每个主题可承载多篇文章。
- **IA-06** 每篇文章必须归属一个且仅一个主要主题，可配置多个标签和知识别名。
- **IA-07** 管理员可新增、改名、排序和归档栏目或主题；不提供直接永久删除入口。
- **IA-08** 阅读者不看到没有已发布内容的空主题；编辑者和管理员仍可在后台看到。
- **IA-09** 管理员归档仍有文章的主题时，必须先迁移全部文章，或连同文章一起归档；不得产生无主要主题的已发布文章。

## 4. 首页

- **HOME-01** 首页按本地时间显示“早上好、下午好或晚上好，{显示名称}”。
- **HOME-02** 问候区域显示固定理念“数据驱动 · 结果闭环”。
- **HOME-03** 首页内容顺序为：问候与全站搜索、新人学习入口、常用模板快捷入口、品质知识入口、散热知识入口、最近更新、推荐书籍。
- **HOME-04** 首页主体保持宽松，不展示复杂分类树、内容统计看板或管理表格。
- **HOME-05** 编辑者额外看到待处理反馈、待复核内容和草稿摘要。
- **HOME-06** 管理员额外看到最近备份状态、账号锁定和服务告警摘要。
- **HOME-07** 管理员可维护问候区域的副标题；产品名称与固定理念不可因普通内容编辑而被改写。

## 5. 新人专区

### 5.1 六阶段路线

- **ONB-01** 新人路线固定以以下六个阶段初始化：
  1. 入职第一天
  2. 认识品质工作
  3. 工作理念
  4. 品质基础
  5. 散热与 TVC 入门
  6. 培训与试用期
- **ONB-02** “工作理念”阶段包含：Reality > Opinion、Ownership > Explanation、Early Exposure > Late Fix、System > Hero。
- **ONB-03** 每个阶段由有序学习步骤组成；每一步可引用一篇已发布文章或一个有效模板，并可附简短说明。
- **ONB-04** 新人专区只作为策展与导航层，不复制文章正文或模板文件。
- **ONB-05** 提供路线总览、阶段编号、“第 N 项 / 共 N 项”、上一篇、下一篇和返回总览导航。
- **ONB-06** 不记录个人已读、完成度、成绩或考试状态。
- **ONB-07** 不提供部门人员目录、头像墙或个人联系方式模块。
- **ONB-08** 管理员可调整阶段说明、步骤引用和顺序，但第一版只提供一条品质部通用路线。

## 6. 知识文章

### 6.1 内容结构

- **ART-01** 知识文章直接在网页中阅读，不允许挂载文件附件。
- **ART-02** 文章字段至少包括：标题、摘要、Markdown 正文、主要主题、标签、内容负责人、状态、更新时间、最近复核日期和下次复核日期。
- **ART-03** 文章状态包括：草稿、已发布、已归档。
- **ART-04** 标题、摘要、正文、主要主题、内容负责人和复核日期是发布必填项；标签与封面图可选。
- **ART-05** 一篇文章可包含多个标签和中文名、英文名、缩写、同义词等知识别名。
- **ART-06** 阅读页展示面包屑、主题、标题、摘要、负责人、更新时间、复核日期、正文目录、正文、标签、相关文章、阅读次数、收藏、反馈和上下篇导航。
- **ART-07** 版本历史入口仅对编辑者和管理员显示。

### 6.2 Markdown 编辑器

- **EDIT-01** 正文底层格式为 Markdown，默认提供类似 Obsidian 的单栏即时预览。
- **EDIT-02** 编辑者可切换纯 Markdown 源码模式或源码与预览左右分栏模式。
- **EDIT-03** 支持标题、粗体、斜体、列表、引用、表格、链接、图片、代码块、LaTeX 行内与独立公式、Mermaid 和站内文章链接。
- **EDIT-04** 支持信息、提示、重点、警告、示例、公式六种 Callout；导出到普通 Markdown 工具后仍应能读出 Callout 标题和正文。
- **EDIT-05** 支持从剪贴板粘贴或从个人电脑上传图片；图片由网站保存，不允许引用员工电脑本地路径。
- **EDIT-06** 编辑器自动保存并显示最后保存时间；断网时保留浏览器临时草稿。
- **EDIT-07** 恢复联网后，服务器版本未变化时自动同步；出现版本冲突时保留两份内容并要求人工选择，禁止静默覆盖。
- **EDIT-08** 发布操作必须在线完成。
- **EDIT-09** 所有编辑者均可编辑全部草稿；当另一人正在编辑时应显示占用状态，并阻止后打开者直接覆盖，可只读查看或在明确确认后接管。
- **EDIT-10** 顶部仅显示常用格式操作，完整操作可通过命令菜单访问；文章大纲和属性面板可按需打开。

### 6.3 发布、版本与归档

- **VER-01** 修改已发布文章时，当前已发布版本继续对阅读者可见，修改内容保存在独立草稿中。
- **VER-02** 再次发布时生成新版本，原版本进入历史；普通阅读者只看到当前已发布版本。
- **VER-03** 编辑者可恢复历史版本；恢复必须填写原因并写入审计日志。
- **VER-04** 编辑者可将文章归档；打开旧链接时显示归档说明、负责人、归档时间和可选替代内容，不默认展示正文。
- **VER-05** 普通站内链接始终指向当前已发布版本；历史版本链接仅编辑者和管理员可访问。
- **VER-06** 支持“创建副本”；副本获得新标识并进入草稿，不继承阅读、收藏、反馈等统计。
- **VER-07** 第一版不支持定时发布或到期自动撤回。

### 6.4 内容复核与负责人

- **GOV-01** 每篇已发布文章必须有内容负责人和下一次复核日期。
- **GOV-02** 到达复核日期后在编辑后台提醒，但不自动隐藏、归档或降级内容。
- **GOV-03** “确认仍然有效”操作更新最近复核日期和下一次复核日期，写入审计，但正文未变化时不生成新版本。
- **GOV-04** 停用负责人的账号前必须指定新负责人，或将其内容放入“待重新分配”队列。
- **GOV-05** 待重新分配内容继续可读，管理员持续看到提醒。

## 7. 模板中心

### 7.1 模板结构与分类

- **TPL-01** 模板是独立下载资源，不作为知识文章附件。
- **TPL-02** 模板字段至少包括：名称、用途说明、适用场景、用途分类、文件、扩展名、大小、适用软件、版本号、版本说明、负责人、状态、更新时间和复核日期。
- **TPL-03** 初始用途分类包括：检验与测试、数据分析与统计、问题分析与改善、风险评估与预防、审核与体系管理、供应商品质、培训与新人、项目与日常管理。
- **TPL-04** 管理员可新增、改名、排序和归档模板用途分类。
- **TPL-05** 不限制模板扩展名；所有文件只存储与下载，不在网页中解析、打开、执行或预览。
- **TPL-06** 默认单文件上限为 500 MB，并允许管理员配置。

### 7.2 版本与下载

- **TPL-07** 新模板版本先保存为草稿，编辑者补齐版本号和变更说明后手动发布。
- **TPL-08** 发布新版本后，旧有效版本成为历史版本；阅读者只看到当前有效版本。
- **TPL-09** 模板链接默认指向模板本身，下载时提供当前有效版本；普通阅读页面不暴露历史版本。
- **TPL-10** 模板副本进入草稿、获得新标识，不默认复制原模板的历史版本或统计。
- **TPL-11** 模板页展示文件扩展名、大小和适用软件，不因格式兼容性弹窗阻止下载。
- **TPL-12** 模板页必须提示：门户中的有效模板不等于 QMS 正式受控版本，使用前需确认正式系统中的最新受控版本。

### 7.3 文件安全

- **FILE-01** 所有模板上传后先进入隔离区，本地恶意文件扫描通过后才能发布。
- **FILE-02** 扫描失败或扫描服务不可用时，不允许把新文件设为有效模板；管理员可查看失败原因并删除隔离文件。
- **FILE-03** 下载响应必须强制附件下载，并安全处理文件名与响应头。
- **FILE-04** 系统记录上传人、文件校验值、下载次数和下载人数。

## 8. 推荐书单

- **BOOK-01** 每本书拥有独立推荐页，包含书名、作者、封面、推荐理由、适合人群、分类、主题标签和推荐人。
- **BOOK-02** 初始分类包括：品质专业、统计与数据、工程技术、管理与沟通、个人成长；管理员可维护分类。
- **BOOK-03** 不提供评分、公开评论、库存或借阅管理。
- **BOOK-04** 封面由编辑者上传，不依赖外部图片服务；封面可选，缺失时显示统一灰度占位图。

## 9. 搜索、收藏与反馈

### 9.1 搜索

- **SEARCH-01** 全站搜索匹配文章标题、摘要、正文、栏目、主题、标签和知识别名。
- **SEARCH-02** 模板搜索匹配名称、用途和版本说明，不读取文件内部内容。
- **SEARCH-03** 书单搜索匹配书名、作者、推荐理由、分类和主题标签。
- **SEARCH-04** 同一知识支持中文名、英文名、缩写和同义词匹配，例如“标准差”“σ”“Sigma”。
- **SEARCH-05** 首页搜索打开居中快速搜索面板，支持键盘上下选择，并按文章、主题、模板和书籍分组展示。
- **SEARCH-06** 回车或“查看全部”进入完整结果页，可按栏目、标签、内容类型和更新时间筛选，并高亮匹配内容。
- **SEARCH-07** 无结果时提示可能别名并允许提交知识反馈。
- **SEARCH-08** 第一版使用 PostgreSQL 搜索能力，不新增独立搜索服务；若实测中文搜索质量未达验收标准，再单独评估专用搜索引擎。

### 9.2 收藏与内容反馈

- **FAV-01** 阅读者可收藏和取消收藏已发布文章；收藏仅本人可见。
- **FAV-02** 第一版不提供最近阅读列表。
- **FDBK-01** 文章页提供内容反馈入口，类型包括：内容错误、内容过期、表述不清、缺少相关内容、其他。
- **FDBK-02** 反馈记录文章、反馈人、说明、提交时间和状态；状态包括待处理、已解决、忽略。
- **FDBK-03** 编辑者可处理反馈；不提供公开评论区。

## 10. 内容统计

- **STAT-01** 记录文章阅读次数；同一用户在 30 分钟内重复打开同一文章只计一次。
- **STAT-02** 编辑预览、管理员预览和自动化访问不计入阅读统计。
- **STAT-03** 按登录账号统计近 7 天、30 天、90 天和全部时间的触达人数。
- **STAT-04** 编辑看板展示热门文章、高触达文章、近期增长文章、长期无人阅读文章、搜索后常打开文章、无结果搜索词、模板下载次数和下载人数。
- **STAT-05** 阅读者只看到文章阅读次数，不看到具体阅读者或触达人员。
- **STAT-06** 仅管理员可在后台查看最近 90 天的身份化搜索和触达明细；编辑者只看聚合统计。
- **STAT-07** 不提供触达人员名单导出；允许导出不含身份的聚合统计。
- **STAT-08** 身份化搜索与阅读明细保留 90 天，之后只保留匿名聚合；聚合统计长期保留。
- **STAT-09** 搜索记录包含搜索词、搜索者、时间和是否有结果。
- **STAT-10** 管理界面明确声明：内容统计用于知识建设，不表示学习成效，不作为个人绩效或培训完成证明。
- **STAT-11** 管理员可执行合规数据清理，但不得单独篡改统计数字。

## 11. 导入、导出与迁移

- **PORT-01** 编辑者可直接新建文章、粘贴内容或导入单个 `.md` 文件。
- **PORT-02** 编辑者可导入包含 Markdown 和图片的标准 ZIP 包；导入内容统一进入草稿。
- **PORT-03** 管理员可批量导入标准 Markdown 包，并在执行前看到新增、跳过和冲突预检结果。
- **PORT-04** 批量导入不得直接覆盖现有内容；冲突必须人工处理。
- **PORT-05** 导入后必须补齐主题、摘要、负责人和复核日期才能发布。
- **PORT-06** 任意文章可连同图片导出为独立可读的 Markdown 包。
- **PORT-07** 管理员可导出全站文章、栏目、主题、标签、别名和业务元数据。
- **PORT-08** Markdown 导出使用 YAML frontmatter 保存标题、主题、标签、负责人、状态、复核时间等信息，并附全站清单文件。
- **PORT-09** 模板文件单独导出，不嵌入 Markdown。
- **PORT-10** 第一版不提供 Word、PowerPoint 或 PDF 到 Markdown 的自动转换。

## 12. 删除、回收与审计

- **DEL-01** 文章、模板、书目、栏目和账号的日常删除操作使用归档或停用，不立即永久删除。
- **DEL-02** 管理员可在回收站恢复内容；回收站保留 30 天后才允许永久清理。
- **DEL-03** 永久清理不得破坏仍由历史版本引用的图片或文件；只有确认无引用后才可删除。
- **AUDIT-01** 审计范围包括：登录成功与失败、账号锁定、用户与角色变化、密码重置、文章和模板生命周期、历史恢复、栏目调整、模板上传下载、搜索、备份与恢复。
- **AUDIT-02** 内容恢复、错误发布回退和归档必须填写简短原因。
- **AUDIT-03** 审计日志至少保留一年，管理员不可通过普通后台操作修改审计内容。

## 13. 安全与数据边界

- **SEC-01** 仅允许受信任公司局域网访问，不设置公网端口转发或远程登录入口。
- **SEC-02** 首版以固定局域网 IP 和 HTTP 提供服务；登录页显示“仅限受信任的公司局域网访问；请勿在公共或访客网络中登录”。
- **SEC-03** 以下任一条件出现时必须升级 HTTPS：公司 IT 可提供内部域名和证书、开始存放内部敏感资料、开放给品质部以外人员、出现远程访问需求。
- **SEC-04** Markdown 禁止 JavaScript、iframe、外部脚本和未清理的危险 HTML；Mermaid 使用安全模式。
- **SEC-05** 允许普通外部链接，但须显示外链标识并在新窗口打开；核心知识和图片不能只依赖外部网页。
- **SEC-06** 图片支持 JPEG、PNG、WebP、GIF 和经安全清理的 SVG，默认单张上限 20 MB；保留原图并生成阅读用版本。
- **SEC-07** 客户、项目和质量案例发布前必须脱敏；案例文章发布时要求编辑者确认已移除客户、项目、人员和可追溯编号，必要时改写数值。
- **SEC-08** 禁止存储客户机密、受 NDA 约束的原始资料、未脱敏图纸和测试数据、员工私人信息、密码密钥、侵权材料、来源不明文件和公司规定必须保存在其他系统的正式记录。
- **SEC-09** 门户用于可复用知识与模板，不替代 QMS、客户数据系统或质量记录系统。

## 14. 部署、存储与运维约束

- **OPS-01** 系统使用 Docker Compose 部署在部门专属 Mac Studio。
- **OPS-02** 至少包含网站服务和 PostgreSQL；反向代理先服务 HTTP，并为后续 HTTPS 保留配置能力。
- **OPS-03** Markdown 正文、版本和业务元数据存入 PostgreSQL，数据库是网页编辑场景的唯一真实来源。
- **OPS-04** 图片、模板和导出包保存在独立受控数据目录，数据库只存元数据和文件校验值。
- **OPS-05** 数据目录不得直接作为公开静态目录；所有访问必须经过登录和权限检查。
- **OPS-06** 字体、图标、脚本、编辑器和运行资源全部本地提供；外网中断时登录、编辑、搜索、阅读和下载仍完整可用。
- **OPS-07** 容器随 Mac Studio 开机自动启动，服务失败后自动重启。
- **OPS-08** 固定 IP 由公司路由器或 DHCP 为 Mac Studio 保留，避免仅在 macOS 手工写死造成冲突。
- **OPS-09** 仅两名指定人员使用各自的 macOS 管理账号执行升级、恢复和故障处理，不共用系统密码。
- **OPS-10** 更新流程必须先备份，再加载版本、执行数据库迁移和健康检查；失败时保留旧版本并提供恢复提示。
- **OPS-11** 不在网页后台提供应用程序在线更新按钮。
- **OPS-12** 服务错误日志保留 30 天。

## 15. 备份、恢复与可用性

- **BKP-01** 每天自动备份数据库、文章、版本、图片和模板文件。
- **BKP-02** 保留最近 7 天每日备份和最近 8 周每周备份。
- **BKP-03** 备份目标支持公司服务器或移动硬盘，部署时可暂不配置目标，但正式上线前必须完成配置。
- **BKP-04** 备份必须加密，至少两名管理员知道恢复密钥的保管位置。
- **BKP-05** 管理后台显示最近备份时间、结果和失败原因。
- **BKP-06** 每季度在临时环境执行完整恢复演练，并验证登录、搜索、阅读和模板下载。
- **AVL-01** 接受计划维护和单机故障期间暂时不可用，不承诺 7×24 高可用。
- **AVL-02** 一般故障恢复目标为 4 小时内；每日备份意味着最多可能丢失 24 小时数据。
- **AVL-03** 计划维护应提前通知用户。

## 16. 响应式、浏览器与无障碍

- **UX-01** 桌面端优先，支持公司常用最新版 Chrome、Edge 和 Safari。
- **UX-02** 手机和平板支持阅读、搜索、收藏和模板下载；编辑器与管理后台保证基本可用，不要求与桌面端等效效率。
- **A11Y-01** 正文默认字号不小于 16px。
- **A11Y-02** 文字和交互控件满足 WCAG AA 对比度。
- **A11Y-03** 全站支持键盘导航和清晰焦点状态，不得只依赖颜色表达状态。
- **A11Y-04** 支持浏览器字体放大至 200%，核心内容和操作仍可使用。
- **A11Y-05** 动画遵守系统“减少动态效果”设置。
- **A11Y-06** 内容图片要求替代文字，纯装饰图可标记为空替代文本。

## 17. 交付里程碑

### 17.1 里程碑一：内容闭环

- 登录、账号和角色
- 首页与一级导航
- 新人六阶段路线
- 品质知识和散热知识
- Markdown 编辑、文章发布与基础版本
- 模板中心
- 推荐书单
- 全站搜索
- 内容管理后台

完成后允许编辑者开始录入真实内容，但不得视为正式上线。

### 17.2 里程碑二：治理闭环

- 完整版本历史和恢复
- 收藏与内容反馈
- 阅读、触达、搜索和下载统计
- 内容复核与负责人交接
- 审计、回收站和安全扫描
- 导入导出
- 自动备份、恢复演练和基础运行监控

两个里程碑均完成并通过验收后，方可正式上线。

## 18. 内容准备与试运行

### 18.1 最低上线内容

- 六个新人阶段全部有说明
- 至少 12 篇新人必读文章
- 至少 20 篇品质知识文章
- 至少 8 篇散热与 TVC 文章
- 至少 10 个有效模板
- 至少 5 本推荐书目
- 首页所有模块均有实际内容，不出现空模块

### 18.2 试运行

正式开放前进行 1–2 周小范围试用，至少包括：

- 1 名新人或近期入职成员
- 2–3 名普通阅读者
- 2 名内容编辑者
- 2 名管理员

试运行必须覆盖登录、搜索、阅读、收藏、反馈、文章发布、模板更新、主机重启、备份和恢复演练。

## 19. 外部前置条件

以下事项不阻塞产品设计，但正式上线前必须落实：

1. 公司 IT 为 Mac Studio 保留固定局域网 IP。
2. 指定两名网站管理员及两名主机维护人员；可以是同一批人，但账号与权限仍须分离。
3. 配置公司服务器或移动硬盘作为离机备份目标。
4. 明确未来申请内部域名和 HTTPS 证书的责任人及触发流程。
5. 完成首批内容整理与案例脱敏。
