# V5.0 架构巡检问题修复

来源：2026-10-20 全项目架构巡检，用户要求逐项解决四个候选。

## 验收范围

1. 知识文章阅读：文章详情、主题列表、栏目树、最近更新、搜索、别名建议、收藏和图片引用授权共用已发布内容查询。编辑中的已发布文章仍显示上一发布版本，正文、标题、摘要、主题、标签、负责人、复核日期与别名均不得从工作区泄露。找不到发布快照时不回退草稿。恢复历史内容到工作区也不提前改变当前发布内容。
2. 知识文章编辑：手动保存、自动保存和发布必须提供预期更新时间；占用被他人接管后原编辑者不能写入。并发检查与写入在同一事务的文章行锁内完成；获取占用、接管、快照及内容写入共享该锁。自动保存只更新提交的正文相关字段，保留其余元数据。页面占用获取失败不进入可编辑模式；失败提示不伪报保存成功，冲突内容可保留。
3. 生命周期与内容审计：知识文章发布、恢复、复核，文章/模板/栏目/主题归档与恢复，永久清理及栏目维护，业务写入与审计一并提交或回滚。模板发布的旧版退役、新版生效、模板状态与审计共用事务；同一模板并发发布只有一个有效版本。文件写入、扫描、备份等外部效果不声称由数据库事务回滚。
4. 备份与恢复：后台与 CLI 的隔离恢复演练共用校验、解密、有效转储检查、恢复 adapter、计数和审计。CLI 只负责参数、连接与输出。保留校验、--drill、--apply；解包只能写入新的目标目录，路径必须留在目标内。演练不覆盖生产数据库，损坏备份不执行恢复命令。

## 兼容与部署

- 保持 ADR 0004 模块化单体及已有 PostgreSQL、文件存储与扫描 adapter；不添加通用 repository 或编辑占用心跳。
- 0016 添加独立发布内容时间、文章版本别名和源更新时间，建立统一阅读视图。历史快照未记录过的别名不能可靠重建，编辑期间按空别名处理，禁止借用当前草稿别名；后续快照完整保留。
- 0017 为模板增加“每个模板仅一个 active”的数据库约束；若历史数据已有重复 active，则迁移失败并要求核实，不擅自选择版本。
- 本次按架构技能需求升主版本 V4.4 → V5.0。发布顺序：本地验证、提交、部署机备份与验收、推送 GitHub 与 v5.0 标签。
