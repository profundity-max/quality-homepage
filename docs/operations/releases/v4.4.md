# V4.4 栏目与主题排序修复 · 2026-10-19

## 原因

用户提供的截图中后台为「0. RCA、1. 问题定义、2. 理解过程」，阅读树却显示「1、2、0」。只读检查生产数据库确认「问题解决」前八个主题的 sort_order 均为 0。

旧新建逻辑固定使用 0，导致重复值累积。旧移动逻辑只寻找排序值严格小于/大于当前值的条目，相同值之间无法移动，还会越过可见相邻项。后台对并列值按名称排序，前台没有对应规则，数据库返回顺序因查询而异。

## 修复

- 管理树和阅读树统一按排序值、名称、稳定标识排序，阅读树只过滤不可见节点，保留相对顺序。
- 移动按同一父级的有效相邻条目交换，再在同一事务内批量写入唯一连续序号，解决已有重复值。归档项不参与移动，边界保持不变。
- 新建栏目和主题追加到有效同级末尾。父节点行锁串行化同级新建和移动；根栏目按固定 ID 次序取得共同锁，避免并发丢失更新。全部保留原角色校验和审计。
- 调整中显示反馈并禁用当前按钮；成功后定位到刚调整的条目。维护操作失效整个页面布局缓存，使阅读侧随之更新。
- 不自动改写生产已有的手工顺序，不做 schema 迁移。
