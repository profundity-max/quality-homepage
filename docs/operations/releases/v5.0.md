# V5.0 架构一致性修复 · 2026-10-20

## 变更摘要

本次逐项解决全项目架构巡检的四个候选，沿用现有模块化单体及 PostgreSQL，不做平台替换。

1. **知识文章阅读一致性**：统一 `readable_articles` 查询，文章详情、主题与栏目、最近更新、搜索、别名建议、收藏和图片授权使用同一发布内容。工作区修改不泄露正文、标题、别名、主题或负责人；缺失快照时不回退草稿。历史恢复先保留当前发布版本。发布内容时间独立于编辑 revision，接管占用不改变阅读更新时间。
2. **编辑占用与保存**：手动保存、自动保存和发布都必须携带预期更新时间，行锁内完成占用检查、并发检查、快照与写入；他人接管后旧编辑者不能继续保存或发布。自动保存使用局部更新，保留主题、负责人、标签、别名和案例标记。冲突时保留本地内容，选择服务器版本重新加载完整状态；界面不提前宣称保存成功。
3. **生命周期与审计**：文章发布、恢复、复核，归档、回收站恢复与永久清理，栏目维护与模板发布在所属模块内部原子提交业务状态与内容审计。模板发布锁定模板行，数据库限制一个模板只有一个有效版本。
4. **恢复演练**：后台和 CLI 共用 operational 模块的校验、解密、恢复 adapter、计数与审计。损坏备份不会执行恢复命令。`--apply` 只解包到新目录，防止覆盖和路径逃逸；`--drill` 只操作自动创建的隔离数据库。

## 数据与兼容

- 0016 增加独立发布内容时间、文章版本别名及源更新时间，并建立统一阅读视图。迁移为既有发布内容回填时间，不改文章正文或分类顺序。
- 旧快照未记录历史别名，无法可靠重建；编辑期间使用空别名，禁止借用当前草稿别名。后续快照保留完整别名。
- 0017 增加模板唯一有效版本索引。部署前只读检查生产重复 active 数为 0；若存在重复，迁移会拒绝而非擅自选版本。
- 数据库事务不回滚文件、扫描或备份等外部效果。
- 本次发现变更 Excel 未包含既有 V4.4 行，依据已有标签及发布说明补记，并追加 V5.0。
